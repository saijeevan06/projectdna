1. Executive summary and product problem

1.1 Product summary

Project DNA is a lightweight AI-assisted project guidance platform for students and developers who want to upskill in AI, improve existing projects, or discover a practical project aligned with a target role. It gives useful project guidance before asking users to register for NxtWave’s “Build Your First AI Project in 60 Minutes” workshop. A simple referral flow and basic growth dashboard help measure whether the experience supports registrations.

1.2 Problem statement

Students and developers often have an existing college or personal project but are unsure which practical AI features would improve it, how to scope the improvements, or how to explain the work for a target role. Users without a suitable project may not know what to build next. At the same time, NxtWave needs a measurable way to attract 500 final-year engineering students to a free 60-minute AI workshop within seven days, with a ₹2,000 campaign budget. Generic promotion links provide little personalized value and weak reasons to share.

Product thesis

Give visitors a useful, personalized project outcome first; make the workshop a natural next step; use optional sharing and source attribution to support measurable acquisition.

1.3 Product positioning

Project DNA is not a code-generation platform, a full repository auditor, a course platform or a workshop delivery system. It is a bounded project-guidance experience connected to a workshop registration conversion path.

2. Goals, non-goals and success metrics

2.1 Goals

Help users receive project improvement recommendations or role-aligned project suggestions with minimal friction.

Present useful results before requiring workshop registration, while keeping the workshop call to action visible on the results page.

Support Gemini as the primary AI provider and Groq as fallback, with deterministic templates when both fail.

Allow a failed or unsupported GitHub URL to be replaced by a pasted README or project description.

Collect and measure registration data in a way that distinguishes demo/test activity from real registrations.

Provide optional unique referral links and an aggregate three-friend progress target without blocking workshop access.

Provide basic channel and conversion metrics to support the campaign plan.

2.2 Non-goals / out of scope

Full repository cloning, source-code crawling, dependency installation, execution, test-running or whole-codebase analysis.

Automatic code edits, pull-request creation, autonomous project implementation or guaranteed production-ready code.

Advanced public college leaderboards, ambassador reward programs, official endorsements or unapproved prizes.

Complex analytics pipelines, attribution across unrelated devices, advertising-platform integrations or predictive growth models.

Contacting students, sending unsolicited bulk messages or executing the real marketing campaign as part of this assessment.

Claiming that the target of 500 registrations has been achieved using simulated data.

Replacing or impersonating NxtWave’s official registration system without an approved URL or integration.

3.2 Path A — Improve my existing project

User chooses “Improve my project.”

User enters a public GitHub repository URL. If fetching fails or the URL is unsupported, offer a paste field for README text or a plain-language project description. Pasting a description must be a first-class fallback, not a dead-end error.

User provides or confirms target role, experience level, relevant technology, interest and available time.

Backend retrieves only bounded public repository metadata and README where feasible. It does not clone or analyze all source files.

AI returns a structured makeover with current-project summary basis, improvement ideas, AI features, technology suggestions, difficulty, estimated time, a basic roadmap, skills and an optional resume bullet.

Results clearly say whether they are based on retrieved README/metadata or on text supplied by the user.

Workshop CTA remains visible on the results page; users can view the result before registering.

3.3 Path B — Find my next project

User chooses “Find a project for my target role.”

User provides user type, target role, experience, preferred technology, interests and time available; branch is requested for student users.

The system selects a small set of suitable items from a curated project catalogue and uses the AI provider to tailor the explanations and roadmap.

Show three recommendations by default. Each result contains problem, expected output, technologies, difficulty, estimated time, skills and a starter roadmap.

If AI providers fail, return curated template recommendations with a visible fallback notice.

3.4 Shared journey

Landing page → choose user type → choose project path → enter minimal relevant information → receive project result → workshop CTA → registration form or approved official registration handoff → confirmation → optional referral link and progress → share to WhatsApp or copy link.

4.1 Registration eligibility and counting rules

Count a campaign-eligible registration only when the record is successfully stored or the approved official registration integration confirms completion, and the registrant meets the final-year engineering-student eligibility rule.

Use normalized email (trimmed, lowercased) as the MVP deduplication key. A duplicate does not increment the eligible registration count a second time.

Demo-mode registrations must be isolated from any production/official registration data and marked visibly in the admin dashboard.

If the product cannot verify final-year eligibility, show “self-reported eligible registration” rather than “verified student”. Do not claim email verification unless implemented.

When handing off to an external NxtWave form, track the CTA click as a click, not as a completed registration, unless an approved return callback or integration confirms completion.

5. UX content and registration conversion

5.1 UX principles

Value before asking: the user can see the main project result before registration is requested.

Keep the workshop CTA visible on the results screen, near the result summary and at the end of the page.

Progressive disclosure: ask only the fields relevant to the selected path; use sensible defaults and “not sure” options where practical.

No dead-end states: URL failure must offer paste fallback; provider failure must offer templates; form errors must preserve user input.

Honest language: label estimated duration, model-generated suggestions, demo data and unverified assumptions clearly.

Mobile-first: all primary forms, cards and share actions work on common mobile viewports.

7. Acceptance criteria

A user can complete either project path without creating an account.

Path A works with a valid public GitHub repository where README retrieval is available, and also works with pasted README or a description if URL retrieval fails.

Path B returns three recommendations from the curated catalogue even when both AI providers are unavailable.

Gemini failure triggers a bounded Groq attempt; if both fail, the user sees fallback content with no broken screen.

The result page includes a visible workshop CTA before registration is completed.

Registration validation prevents duplicate normalized emails from incrementing registration totals.

Referral progress updates only from new valid registration records; referral is not required to access or register for the workshop.

Admin analytics distinguishes demo activity from production/official records and eligible final-year students from non-eligible users.

No API key is sent to the browser. A non-admin cannot read the registration list or admin metrics.

All required assessment deliverables can be demonstrated or explained without contacting students or executing the campaign.

10. Assumptions to verify before production

The official workshop registration URL or endpoint is supplied and authorized before claiming that a registration was completed by NxtWave.

Any use of the NxtWave name, logo, workshop statements or promotional material follows assessment and brand rules.

AI provider keys and database credentials are available for deployment; otherwise the app runs in a labelled demo/template mode.

Only minimal personal data is collected and no outreach is sent to friends or students by the app.
